## Runtime, scale and output

The primary workflow is `./setup.sh`, then `./run.sh --input companies.jsonl --output output.jsonl`. Installation needs outbound HTTPS, `curl` for the bootstrap and CPython 3.12+; no system Tesseract, LLM or personal API key is required. This pass inspected these wrappers but did not execute setup or research.

The total-budget interface is implemented: `--budget-seconds` overrides `SIGNALPOST_BUDGET_SECONDS`, which overrides config; default total is **1,800 seconds**. An explicit total reserves `min(300 seconds, 20% of total)` for finalization inside that total. Without an explicit total, configured defaults remain 1,800 hard / 1,350 soft / 300 reserve. These settings are project controls, not organizer limits. The final-source deadline behavior, including slow filesystem/publication paths, has not been measured as a hard-wall guarantee.

Fresh final-source 100-company acceptance and **1,000-company scale/runtime checks are pending**, including cardinality, order, duplicates, failures, budget exhaustion, publication integrity and resume/refresh. Historical or synthetic throughput is not a measured 1,000-company live result. One terminal envelope per input row is the repository contract, not proof that every field is populated. Official evaluator/parser compatibility and organizer-supplied resource limits remain unverified. The site exporter and human profile have implementation and focused-test coverage in the working tree; the final site export itself has not been run or reviewed.
