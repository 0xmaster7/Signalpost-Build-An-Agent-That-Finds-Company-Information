# M01 implementation decisions

Date: 2026-10-03 (Asia/Kolkata)

## Canonical contract

`signalpost.models` owns the internal Pydantic contract. It has the seven content/cross-cutting sections from plan §4.1, the six public terminal states, and first-class claims, evidence, source snapshots, refresh state, errors, and operations. `signalpost.adapter` is the only vendor-named boundary. Its checked-in golden fixture captures the currently known public semantics; it is explicitly provisional because Builderr has not published an exact JSON Schema or field/version fixture.

Each input row keeps its own `input_ref` and output envelope, including duplicate organisation numbers. Invalid and malformed rows are isolated and produce a failed envelope. A wrong checksum is only a sanity anomaly: an exact frozen registry row still permits processing, as required by the audited plan. Available claims carry the plan's entity, section, family, subject, scope, verification, evidence, and source-snapshot provenance.

## Runtime and request control

`python -m signalpost.run` accepts JSON, JSONL, CSV, TSV, and plain text. It reads a frozen registry fixture for deterministic offline operation, creates SQLite pending shells for all input rows before enrichment, checkpoints final envelopes, and atomically writes ordered JSONL. No M01 provider or search request is enabled. A missing fixture match is represented as a failed registry lookup with an explicit `REGISTRY_SNAPSHOT_MISS`; this is not interpreted as evidence that the company is absent.

`signalpost.network.NetworkGateway` centralizes physical HTTP attempts, safe redirects, direct-mode DNS/IP checks, trusted-proxy policy, robots retrieval and RFC 4xx behavior, conservative 5xx/network handling, crawl delay, host/global concurrency and optional budget reservation. Response bodies have compressed and expanded caps. Robots meta/header directives are exposed for downstream extraction. The quarantined starter experiments remain outside this production entry point; later production connectors must use this gateway.

`RunBudget` uses the audited fallback: 1,800-second hard limit, 1,350-second soft deadline, 300-second completion reserve, `12*N+1000` physical-request allowance pending Builderr's numeric cap, and zero paid cost. The evidence cutoff defaults to the M00 safety target of 2026-10-17 23:59 IST. Deployment config or `SIGNALPOST_*` values can override budget/cutoff values. We do not claim compliance with an unknown official budget.

## Remaining Builderr inputs

The exact evaluator JSON Schema/version, official numeric request/time/cost budgets and environment names, duplicate semantics, prior-state format, and evidence-cutoff timezone remain unresolved. M00 defaults remain in force. Search remains disabled. M02 should replace the fixture-only registry path with the streamed frozen snapshot and live BRREG client, both through the gateway, while preserving row cardinality, checksum anomaly behavior, evidence requirements and the six-state mapping.
