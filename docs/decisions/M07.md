# M07 decision record: refresh and history

## Canonical handoff

- `--previous-state` consumes only schema-versioned canonical JSON. Each company key, identity fingerprint, claim, evidence reference, snapshot reference, source-policy version, configuration fingerprint, and cutoff is validated before comparison.
- `--state-output` writes the next canonical JSON artifact atomically. `--checkpoint` owns SQLite resume state; its default is the state-output path plus `.checkpoint.sqlite`.
- A missing prior artifact means baseline. A malformed, unsupported, wrong-identity, or incompatible artifact produces an explicit `REFRESH_PRIOR_STATE_INCOMPATIBLE` row error and no change events from that artifact.
- Schema version 1 is accepted. Unknown versions fail closed until an explicit migration exists.

## Identity and comparison

- The exact organisation number is the company identity key. A stable snapshot-content ID hashes source URL plus content hash; an observation ID additionally includes retrieval time.
- Fact fingerprints include target, section/family, subject, field, normalized value, reporting period, unit, currency, scope, and effective/as-of date. Retrieval time, evidence ordering, and claim IDs are excluded.
- Equivalent URL spelling, Unicode composition, and whitespace do not create value changes. Financial periods remain separate. A changed fact for the same financial period is typed as a corrected filing; zero remains a valid value.
- No prior state creates no additions. Post-cutoff facts are excluded. Unknown effective dates remain unknown.

## Retention and removal

- Facts remain in the next state when the current source was not attempted, failed, blocked, malformed, or incomplete. Missing website, job, and activity observations do not imply closure.
- Role removals require a current complete BRREG roles collection and its completion evidence. Workplace removals require a complete paginated BRREG subunit collection and a content-hashed evidence item for every returned page. Malformed role responses do not produce completeness evidence.
- Explicit source unavailability may be recorded as an observation when the response has valid source evidence; it never deletes retained facts.

## Publication boundary

- Canonical change events live under `refresh.changes`; only `signalpost/adapter.py` maps their supported names into the provisional evaluator shape.
- Every event carries prior/current state references, claim fingerprints, relevant evidence references, and an effective date only when source claims provide one. Removal events also carry the collection-completeness evidence references.
- The configured runtime identity and a content hash of the source-policy, source-rights, and BRREG policy documents must match between state artifacts. Snapshot bytes are recorded as provenance and remain part of the SQLite resume fingerprint, but are allowed to change between prior and current refreshes.

## Remaining external inputs

Builderr has not supplied the exact prior-state handoff or final change-event enum schema. The current fallback is the versioned canonical JSON artifact and the provisional adapter mapping above. No paid API, model, search provider, or additional credential is enabled.
