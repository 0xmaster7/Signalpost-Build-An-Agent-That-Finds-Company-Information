# M02 implementation decisions

Date: 2026-10-03 (Asia/Kolkata)

## BRREG foundation

### Structured API and robots transport failures

The gateway records a robots-rule disallow separately from a robots retrieval failure. Ordinary website crawling remains fail-closed on timeout, reset, 5xx, oversized or unusable robots responses. Transport/server failures are `robots_unreachable`; oversized or challenge/unusable responses are `robots_unusable`. A retrieved explicit disallow continues to block every path, including BRREG API paths.

M02's official BRREG calls are documented structured API GETs, not website crawling. The audited plan applies the robots outage skip to non-essential crawling; the M01 starter also scoped robots checks to website access while its official BRREG connector called structured registry endpoints directly. Accordingly, the gateway permits continuation only after a robots transport failure or 5xx for the registered `brreg_structured_api` profile, whose exact host, endpoint paths, and request purposes are allowlisted in code. Explicit disallows, oversized/challenge/unusable responses, and excessive crawl-delay policy skips remain blocked. The API remains behind the M01 gateway, request ledger, SSRF checks, redirects, source-host restrictions, and pacing. The live host check confirmed documentation/API access succeeds while `/robots.txt` resets after receiving the GET; this reset is recorded as unreachable, never as an explicit disallow.

- `signalpost.brreg` is the production structured-data adapter. It performs no network I/O itself: entity, normalized accounts, roles, and all subunit pages go through `NetworkGateway` and its request ledger.
- The legal entity remains anchored to the exact nine-digit requested organisation number. A subunit's parent stays a relationship; role-holder organisations and group members stay separate subjects. Group lookups are not on the 100-company critical path.
- Frozen registry files are filtered in a stream and hashed from source bytes. When Builderr's authoritative snapshot format/date/source is supplied, it can be passed explicitly; without it, exact-org live BRREG is the documented identity fallback. Both baseline and live observations are retained separately when a dated baseline is supplied.
- Account history retains every distinct source record and correction/version, all seven exact-labeled metrics, source periods, filing/version metadata, source currency/unit when present, and legal-entity/group/unknown scope. No year is inferred, and missing values remain unclaimed.
- Role-holder identifiers are values on target-scoped role claims, never target replacements. Birth dates and personal identifiers are discarded during normalization. ENK identity fields do not include owner-private or personal-register data.
- Every published structured fact has exact-source content hash, JSON pointer, extraction method, retrieval time, and a source snapshot reference. NLOD attribution and retention handling are documented in `docs/sources/brreg.md`.
- The 100-company smoke fixture uses a stable SHA-256 bottom-k sample of the M00 2025 filer universe. It is an input fixture only; that derived archive is not represented as a complete or authoritative frozen registry snapshot.

## Authoritative identifier correction

During M02 sample validation, the M01 checksum helper was found to use weights that disagree with BRREG's published organisation-number specification. BRREG documents weights 3, 2, 7, 6, 5, 4, 3, 2 over the first eight digits and rejects the check digit 10. The helper now follows that source. Exact frozen-row matches remain processable if a checksum anomaly is present, as recorded in M01; the checksum never substitutes for the exact source organisation-number match.

Source: [BRREG, About the organisation number](https://www.brreg.no/en/about-us-2/our-registers/about-the-central-coordinating-register-for-legal-entities-ccr/about-the-organisation-number/).

## Active Builderr fallbacks

The provisional evaluator adapter and M00 defaults remain active: six-state mapping, one output per input row, cutoff `2026-10-17T23:59:00+05:30`, 1,800-second hard budget / `12*N+1000` physical attempts / zero paid cost. No search or model provider is enabled. Frozen snapshot source path, date, and exact Builderr evaluator schema remain external inputs; no M02 implementation depends on them to run.
