Runtime config may record `website_rights_decisions`, mapping an exact hostname or its registered domain to `allowed`, `blocked`, or `unknown_not_reviewed`. Missing entries remain `unknown_not_reviewed` and are exposed in candidate audit rows and website snapshots; this is not represented as a license. An explicit `blocked` decision takes precedence at either hostname level and skips the candidate before robots or page requests. This is a bounded, auditable input; Signalpost does not fetch or interpret terms pages automatically.

The audited plan's robots transport/server failure rule is for non-essential website crawling: skip that origin and record `ROBOTS_UNREACHABLE`. M02's documented structured BRREG API calls are governed separately as official API requests. They remain subject to explicit retrieved robots disallows, host/path allowlisting, SSRF checks, rate limits, redirects, request accounting, and source terms. On a robots transport reset or 5xx, only the exact documented `data.brreg.no` structured API paths may continue; ordinary website and page requests remain fail-closed with the distinct `robots_unreachable` outcome. Oversized or challenge/unusable robots responses fail closed for the API too. A transport reset is never recorded as an explicit disallow.

M02 excludes person birth dates, national identifiers, private addresses, private contact details, and unrelated personal profiles. ENK business and postal registration addresses are omitted because they may be an owner's home address. Role names, role, dates, and public business relationships may be retained. The frozen Builderr snapshot's specific licence, source URL, as-of date, and retention terms remain parameters until supplied; do not infer that snapshot's licence from BRREG's API licence.

Attribution text for BRREG-derived facts: “Source: Brønnøysund Register Centre (Brønnøysundregistrene), retrieved [date], licensed under NLOD 2.0.”

M03 website crawling does not use the BRREG structured-API robots exception. If an ordinary website's robots file is disallowed, unusable, or unreachable, its pages are not fetched. A transport/server failure is recorded as `ROBOTS_UNREACHABLE` (not as an explicit disallow); the site research state is failed for that attempt. Exact ownership still requires a subject-scoped identity proof before any site-derived claim can be published.

## Public discovery additions — 26 October 2026

- **NAV:** [official API documentation](https://navikt.github.io/pam-stilling-feed/), [live OpenAPI](https://pam-stilling-feed.nav.no/api/openapi.json), [data-use terms](https://arbeidsplassen.nav.no/vilkar-api). Those terms permit metadata analysis and require updates/removal for republished ads. We retain only allowlisted job metadata and source provenance, never raw descriptions, contact lists or tokens. Every published posting requires current ACTIVE detail, future expiry, publication/modification dates and exact employer orgnr or an evidenced official workplace-parent relation. Refresh does not retain unrefreshed NAV ads and does not infer closure from missing results. The public experimental token is fetched at runtime and kept in memory; its availability is not guaranteed. API redirects are rejected; explicit robots disallows remain binding, with an outage exception only for the exact documented NAV API paths. NAV vacancy data is **not** labelled MIT. The scan is deliberately partial and cannot establish absence of jobs.
- **Wikidata:** [structured-data licensing](https://www.wikidata.org/wiki/Wikidata:Licensing) is CC0. P2333/P856 results are discovery candidates only, not company facts or ownership evidence. The 26 October live check found `Disallow: /sparql` on the query endpoint. Production respects that rule and records the source as blocked; no alternate route bypass is used.
- **Registry URLs:** an exact-entity BRREG homepage declaration may be published as `registry_declared_website_url`, or `shared_website` for known shared roots, citing only the registry response. This does not license/crawl the declared website or attribute its content. Conflicting observed identity and cross-host redirects withhold the declaration fallback. Inferred/email/workplace/NAV/Wikidata leads cannot use this tier.
