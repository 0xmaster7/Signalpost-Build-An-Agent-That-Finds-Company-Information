# M04 discovery method and provider decision

M04 keeps discovery separate from publication. The existing registry URL and one distinctive-name `.no` candidate remain the reproducible production discovery paths. Registry-only and registry-plus-keyless runs are compared on the same ordered cohort. The keyless mechanism is the audited M03 one-candidate rule; M04 does not add speculative suffix combinations or a broad domain crawler.

`signalpost.discovery.SearchProvider` defines the optional adapter boundary and `MockSearchProvider` supports deterministic tests. Search query order follows the audited plan: organisation number plus legal name, legal name plus municipality, then an already verified public brand plus municipality. A provider must be reproducible, rights-approved, expose retries, predeclare its per-query cost, and account for physical requests through `NetworkGateway` or an equivalent visible ledger. Provider results are reduced to safe URL candidates and trace metadata. Titles, snippets, ranks, and generated text cannot become facts. Search candidates require subject-scoped structured organisation-number proof; directory paths, known directory hosts, and third-party profile pages stay ambiguous. The website pipeline must independently fetch the candidate and pass M03 exact-company identity proof before publishing any website claim.

No reproducible, rights-approved search provider is configured. Search therefore stays disabled in production. No search credential is required to complete M04 under audited plan §18.6 and §M04: releases may keep search disabled when the deterministic path and remaining gates pass. No paid service or model was used. The mock fixture generates no network traffic and is not a production provider.

The M04 benchmark reports raw candidate and exact-domain counts for registry-only and registry-plus-keyless runs alongside the committed M03 measurements. It uses `docs/audit/m00-company-sample-200.jsonl`, SHA-256 `cee97e17af7e8b2d9dc9f5ee60548b9e186a11a2e485469446219ea10a1e38ed`. The frozen source is candidate-only because its rights remain unresolved. `docs/audit/m04-discovery-benchmark.json` contains decisions, state distribution, exact-site proof checks, physical/logical requests, runtime, cost and the raw M03-to-M04 deltas. Candidate count is not recall. The cohort is the existing 200-row opportunity sample, not an independent human-adjudicated promotion audit; no population precision percentage is reported. Search-derived promotion remains off, so the >=300-decision gate for weaker-than-strong-proof search acceptance is not claimed as satisfied.

The active fallback is registry candidates plus the bounded keyless `.no` guess, followed by M03 verification. Provider outage or absence must leave discovery unresolved/ambiguous as applicable; it cannot create a zero or absence fact.
